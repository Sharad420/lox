# jlox

A tree-walking interpreter for Lox, written in Java. See the [top-level README](../README.md) for how it compares with clox.

## Design notes

### Pipeline

Source → scanner → tokens → parser → AST → resolver → interpreter.

- The scanner reads the whole file into a list of tokens up front.
- Recursive descent parser: one method per grammar rule, with precedence encoded by which rule calls which.
- After a syntax error, the parser synchronises at the next statement boundary and keeps going, so one run reports several errors.

### Syntax tree

- AST classes are generated by a script (`GenerateAst`) rather than written by hand.
- Each pass over the tree (resolver, interpreter, AST printer) is a Visitor, so adding a pass doesn't touch the node classes.

### Resolver

- A static pass between parsing and interpreting. For each variable reference, it records how many scopes away the declaration is.
- The interpreter uses that distance, so a closure keeps referring to the variable it saw when it was declared, even if the enclosing scope declares a same-named variable later.
- Also reports static errors: reading a local in its own initialiser, redeclaring a local, `return` outside a function, returning a value from `init`, `this` outside a class, and `super` outside a subclass.

### Variables and scope

- Each scope is an `Environment`: a `HashMap` from name to value, plus a link to the enclosing environment.
- Globals are the outermost environment and are looked up by name, so a function can use a global declared after it.
- Locals are looked up by walking the resolved number of hops up the chain.

### Functions and closures

- `LoxFunction` wraps a declaration and the environment it was declared in. That environment is its closure.
- Each call creates a new environment for the parameters, whose parent is the closure.
- Calls recurse on the Java stack, so very deep Lox recursion causes a `StackOverflowError`.
- `return` is a thrown exception that unwinds to the call. Stack traces are disabled on it to keep it cheap.
- Natives (`clock`) implement the `LoxCallable` interface like Lox functions.

### Values

- Lox values are Java objects: `Double`, `String`, `Boolean`, `null` for nil, and instances of the runtime classes.
- `nil` and `false` are falsey; everything else is truthy.
- Equality uses Java's `equals`, so `(0/0) == (0/0)` is true in jlox, unlike in clox and IEEE 754.
- Memory is managed by Java's garbage collector.

### Classes

- `LoxClass` holds a map of methods and a pointer to its superclass. Method lookup walks up the superclass chain.
- Accessing a method binds `this` by wrapping the method's closure in a new environment that defines `this`.
- `super` is stored in an environment around the subclass's methods, at a fixed distance found by the resolver.
- `init` always returns `this`, even when called directly.

### Errors

- Runtime errors are Java exceptions carrying the token where they happened, which gives the line number.
- Exit codes: 65 for syntax errors, 70 for runtime errors.
